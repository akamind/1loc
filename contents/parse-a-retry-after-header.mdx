title: Read a Retry-After header
---

**JavaScript version**

```js retryAfterMs.js
function retryAfterMs({ retryAfter, date }) { const seconds = Number(retryAfter); return Math.max(0, Number.isFinite(seconds) ? seconds * 1000 : Date.parse(retryAfter) - Date.parse(date)); }

```

**TypeScript version**

```ts retryAfterMs.ts
function retryAfterMs({ retryAfter, date }: { retryAfter: string; date: string }): number { const seconds = Number(retryAfter); return Math.max(0, Number.isFinite(seconds) ? seconds * 1000 : Date.parse(retryAfter) - Date.parse(date)); }
```

**Examples**

```js examples.js
retryAfterMs({ retryAfter: '30', date: 'Wed, 28 Oct 2026 14:00:00 GMT' }); // 30000
retryAfterMs({ retryAfter: 'Wed, 28 Oct 2026 14:00:30 GMT', date: 'Wed, 28 Oct 2026 14:00:00 GMT' }); // 30000
```

**Notes**

- An HTTP date is compared with the response’s own `Date` header, not your clock, so clock skew cannot shorten the wait.
- Oveyon answers rate limiting with HTTP 429 and `Retry-After`. Wait at least this long, then retry with the same idempotency key.
